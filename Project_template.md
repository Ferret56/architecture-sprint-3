### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

Пользователи могут:
  - удалённо включать/выключать отопление в своих домах
  - устаналивать желаемую температуру
  - управлять состоянием системы отопления

**Мониторинг температуры:**

Пользователи могут:
  - получать основную информацию о состоянии системы отопления 
  - получать текущую температуру

Система может:
  - получать данные о температуре с датчиков, установленных в домах 

### 2. Анализ архитектуры монолитного приложения

- **Язык программирования**: Java
- **База данных**: PostgreSQL
- **Архитектура**: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения.
- **Взаимодействие**: Синхронное, запросы обрабатываются последовательно.
- **Масштабируемость**: Ограничена, так как монолит сложно масштабировать по частям.
- **Развёртывание**: Требует остановки всего приложения

### 3. Определение доменов и границы контекстов

**AS-IS**:
 - домен управления системой отопления
   - изменение температуры
   - изменение состояния системы
   - влючение/выключение отопления
 - домен мониторинга системы отопления
   - получение основной информации о состоянии системы отопления
   - получение текущей температуры
 - домен управления датчиками отопления
   - регистрация устройств
   - получение информации с устройств

### **4. Проблемы монолитного решения**

- сложность разработки из-за общей кодовой базы
- невозможность горизонтального масштабирования и тесная связь отдельных компонентов системы
- единая точка отказа: при отказе одного из компонентов вся система оказывается в нерабочем состоянии
- сложность при разворачивании приложения: компилировать и деплоить нужно всё приложения целиком,
  даже если изменился только отдельный компонент системы
